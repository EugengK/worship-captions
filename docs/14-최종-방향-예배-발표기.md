## 2. 결정 [의견]
**B. 자체 예배 발표기를 주 방향으로 합니다.** 이유는 세 가지입니다.
1. 이 프로젝트의 핵심 기능들이 모두 **"우리가 화면과 슬라이드를 직접 다룰 수 있을 때"만 확실하게** 됩니다.
   - 자막 띠
   - 슬라이드 연동 켜기/끄기
   - 고정 슬라이드의 태국어
   - 휴대폰 연동
2. 가장 큰 기술 위험이었던 "이음오피스 엔진을 앱 밖에서 쓸 수 있나"는 **확인했습니다**.
   - pptx 읽기
   - 1920×1080 그리기 정보 생성
   - 발표자 노트 읽기
3. A안(Keynote)은 지금 편하지만, 위의 기능마다 Keynote가 허락하는 범위 안에서만 됩니다.

**남은 관문:** 목사님의 실제 예배 pptx(Keynote에서 내보낸 것)가 **충분히 똑같이 보이는지**입니다.
- 이것이 안 되면 A안으로 돌아갑니다.
- 서버, 번역, 휴대폰, 켜기/끄기 논리는 어느 쪽이든 그대로 씁니다.

## 3. 매주 작업 흐름 (2026-10-30 정정: 제작은 PowerPoint)
> 정정: 목사님과 PPT 봉사자는 **PowerPoint로 제작**하고, 교회 MacBook Air에서는 그 pptx를 **Keynote로 열어 발표**해 왔습니다. 따라서 Keynote → pptx 변환 단계가 **필요 없습니다.**

1. 지금처럼 **PowerPoint로 예배 PPT 작성** (.pptx 그대로)
2. 순서가 바뀌는 슬라이드의 **슬라이드 노트**에 `[번역 ON]`(설교·기도·광고) / `[번역 OFF]`(찬양·찬송·성경 봉독·신앙고백)
   - 표시가 없으면 앞 슬라이드 상태를 이어감. 매주 쓰는 원본 틀에 한 번 넣어 두면 유지됨
3. 예배 발표기로 pptx를 바로 열기 → 노트북: 발표자 화면 / 프로젝터: 슬라이드 + 자막 띠

**의미 [의견]:** 이음오피스 엔진은 처음부터 PowerPoint(.pptx)를 읽도록 만들어졌으므로, Keynote에서 변환한 파일보다 **PowerPoint 원본이 재현 품질 면에서 유리**할 것으로 봅니다. 그래도 실제 예배 파일로 확인하는 관문은 그대로입니다.

## 4. 개발 순서
| 단계 | 내용 | 확인 방법 |
|---|---|---|
| 1 | 발표기 시제품: pptx 열기 → 프로젝터 전체화면(청중) + 노트북(발표자: 현재/다음 슬라이드) → ←/→ 키·클리커 | 목사님 맥에서 **실제 예배 pptx로 재현 품질 확인** (관문) |
| 2 | 자막 띠 내장 + 노트의 `[번역 ON/OFF]`로 엔진 자동 켜기/끄기 (끈 동안은 Google에 소리를 보내지 않음 → 비용 절약) | 새벽예배에서 시험 |
| 3 | 영상 재생, 전환 효과 | 예배 pptx의 영상 슬라이드 |
| 4 | 고정 슬라이드 태국어(미리 번역), 성도 휴대폰 연동 | – |
