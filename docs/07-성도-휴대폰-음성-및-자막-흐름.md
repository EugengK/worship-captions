# 성도 휴대폰 음성 듣기 + 화면 자막의 흐름 (v0.7)

작성일: 2026-10-26
> 표기: **[확인]** 시험·자료로 확인 / **[의견]** Claude의 설계 판단 (구현하며 검증)

## 1. 성도 입장에서의 사용 순서
1. 예배당 화면이나 주보의 **QR 코드**를 휴대폰으로 찍습니다. **앱 설치 없이** 웹페이지가 열립니다(아이폰·삼성 모두).
2. 언어를 고릅니다: `English` / `ไทย` / `中文` …
3. **"듣기 시작"** 버튼을 한 번 누릅니다. 휴대폰 브라우저는 사용자가 버튼을 눌러야 소리를 낼 수 있게 되어 있어서 이 단계가 꼭 필요합니다.
4. 이어폰(유선·블루투스 모두 가능)으로 **자기 언어의 통역 음성**을 듣습니다. 화면에는 같은 언어의 **자막 글자**도 함께 흘러갑니다.
   - 예) 태국 자매님 → 태국어 음성 + 태국어 글자 / 영어권 방문자 → 영어 음성 + 영어 글자

## 2. 뒤에서 일어나는 일 (구조) [의견]

```
[목사님 핀마이크] → [MacBook Air] ──마이크 소리──> [교회 중계 서버 (클라우드)]
                        │                              │
                        │                              ├─ 영어 통역 세션 (Gemini) ──> 영어 음성·글자 ─┐
                        │                              ├─ 태국어 통역 세션 (Gemini) ─> 태국어 음성·글자 ┤
                        │                              └─ 한국어 원문 글자 → 원고 추적기               │
                        │                                                                               │
                        ▼                                                                               ▼
               프로젝터 하단 자막  <──────────── 자막 글자 ────────────  성도 휴대폰 (언어별 음성 + 글자)
```

- **왜 중계 서버가 필요한가:** 성도 휴대폰은 교회 Wi-Fi나 모바일 데이터 등 제각각의 인터넷으로 접속합니다. 그 휴대폰들이 맥에 직접 붙기는 어렵습니다. 그래서 인터넷 위에 **작은 서버**를 하나 두고, 맥은 마이크 소리만 올립니다. 서버가 통역하고 휴대폰들에 나눠 줍니다.
  - 오래된 맥은 "소리 보내기 + 자막 화면 띄우기"만 하면 되므로 부담이 적습니다.
  - API 키는 서버에만 두고, 성도 휴대폰에는 절대 내려가지 않습니다.
  - 서버 비용: 소규모라 무료~월 몇 달러 수준으로 예상합니다(서비스 선택 후 확정).
- **언어 하나 = 통역 세션 하나:** Gemini 실시간 통역은 연결 하나에 **목표 언어 하나**만 설정합니다 [확인: SDK 설정 `target_language_code` 단일 값]. 영어와 태국어를 동시에 들려주려면 세션이 2개 필요하고, **비용도 2배**입니다.
  - 그래서 **"듣는 사람이 있는 언어만 켜기"**로 만듭니다. 태국 자매님만 오신 날은 태국어 세션 1개, 영어권 손님도 오신 날은 2개가 자동으로 켜집니다. 아무도 듣지 않는 언어에는 비용이 들지 않습니다.
  - 예상 비용 [의견, 보도 단가 기준]: 언어당 시간당 약 $1.4~2.2.

## 3. 화면(프로젝터) 자막은 어떻게 만들어지나 [의견]

**프로젝터 하단 2줄**: 위 영어, 아래 태국어처럼 **예배 전에 설정에서 고른 언어**가 나옵니다.

자막 문장은 아래 우선순위로 정합니다.
1. **원고와 일치할 때** → 예배 전에 용어집을 적용해 **미리 번역해 둔 문장**을 띄웁니다. 가장 정확합니다.
2. **원고와 다를 때**(애드리브, 기도, 광고) → 그 언어의 통역 세션이 켜져 있으면 **그 세션의 번역 글자**를 띄우고, 꺼져 있으면 **텍스트 번역 모델**로 즉석 번역합니다(원고 문맥 + 용어집 반영).

| 상황 | 켜지는 통역 세션 | 화면 자막 출처 |
|---|---|---|
| 아무도 이어폰으로 듣지 않음 | 한국어 인식 1개만 (또는 영어 세션 1개) | 원고 번역 + 텍스트 모델 |
| 태국 자매님이 태국어로 들음 | 태국어 1개 | 원고 번역 + 태국어 세션 글자 |
| 태국어 + 영어 청취자 | 2개 | 원고 번역 + 각 세션 글자 |

- **휴대폰 글자 vs 프로젝터 글자:** 휴대폰에는 지금 듣는 **음성과 똑같은 실시간 글자**가 나옵니다. 프로젝터에는 원고와 맞으면 **미리 번역한 더 정확한 문장**이 나옵니다. 그래서 표현이 조금 다를 수 있습니다.

## 4. 알아 두실 한계와 대책
| 한계 | 내용 | 대책 [의견] |
|---|---|---|
| **지연** | 첫 시험에서 말 시작 후 **약 4~5초 뒤**부터 통역이 나왔습니다 [확인] | 동시통역사와 비슷한 수준. 원고 일치 시 화면 자막은 더 빨라질 수 있음 |
| **휴대폰 화면 잠금** | 웹페이지 방식은 휴대폰 화면이 잠기면 **소리가 끊길 수 있습니다**(특히 아이폰) | 페이지에 "화면 켜두기" 기능(Wake Lock)을 넣고, 실제 기기에서 시험. 문제가 계속되면 나중에 전용 앱 검토 |
| **데이터 사용량** | 압축하지 않은 음성은 시간당 약 170MB | 음성 압축(Opus 등)으로 시간당 약 10~20MB 수준까지 낮춤. 교회 Wi-Fi 이용 권장 |
| **이어폰** | 이어폰 없으면 옆 사람에게 소리가 들림 | 안내 문구. 교회에 저렴한 유선 이어폰을 몇 개 비치 |
| **인터넷** | 교회 인터넷이 끊기면 전부 멈춤 | 맥은 유선 연결 권장. 휴대폰은 모바일 데이터로도 가능 |

## 5. 구현 순서 (실시간 통역 일시 보류 후 재개 시)
1. 중계 서버 + 성도용 웹페이지(언어 선택·듣기·글자) 시제품 → 미리 녹음한 음성으로 휴대폰 2대(아이폰·삼성)에서 시험
2. 화면 잠금·블루투스 이어폰·데이터 사용량 확인
3. 프로젝터 자막 페이지와 원고 추적기 연결
