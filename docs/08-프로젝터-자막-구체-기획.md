# 프로젝터 자막 구체 기획 (v0.8)

작성일: 2026-10-26
> 표기: **[확인]** 자료·시험으로 확인 / **[의견]** Claude의 판단 / **[검증 필요]** 예배당 현장 시험으로 확인해야 함

## 1. 현재 운영 방식 (목사님 설명)
- MacBook Air + 프로젝터를 **듀얼 모니터(확장 디스플레이)**로 씀
- Keynote 발표 화면은 **프로젝터(1920×1200, 16:10)**로, 발표자 화면은 **노트북**에 둠
- 예배 순서에 따라 Keynote 파일을 계속 수정함 → **Keynote 운영 방식은 바꾸지 않는 것이 원칙**

## 2. 선택지 비교

| | 방식 | Keynote 운영 변화 | 장점 | 단점·위험 |
|---|---|---|---|---|
| **A (추천)** | **자막 오버레이 프로그램**: 프로젝터 화면 하단에 **투명하고, 항상 위에 있고, 클릭이 통과되는 창**을 띄우고 그 안에 자막 웹페이지를 표시 | **없음** | Keynote를 지금처럼 그대로 씀. 자막 화면은 웹페이지라 디자인 수정이 쉬움 | **Keynote 슬라이드쇼 위에 창이 실제로 떠 있는지**가 핵심 위험 [검증 필요] |
| B (대안) | Keynote **"윈도우에서 재생"** [확인: [Apple 가이드](https://support.apple.com/guide/keynote/tan72233051/mac)]으로 슬라이드는 위쪽, 자막 창은 아래쪽에 나란히 배치 | 재생 메뉴만 바꿈 | 창끼리 겹치지 않아 기술적으로 단순 | 창 테두리가 보일 수 있음. 이 맥의 Keynote 버전에 메뉴가 있는지 [검증 필요] |
| C (장기) | Keynote를 **이미지로 내보내 웹 슬라이드 플레이어**로 띄우고 자막을 그 안에 통합 (HTML로 PPT처럼 보여주는 방식) | **큼** (매주 내보내기) | 화면 전체를 우리가 제어. 나중에 성경·찬양 자막까지 통합 가능 | 애니메이션·영상이 사라짐. 매주 작업 추가 → **지금은 비추천** |

### [의견] 결정: **A로 시작하고, 안 되면 B로 갑니다.** C는 나중의 확장 옵션으로 남겨 둡니다.

## 3. A안 상세: 자막 오버레이 프로그램

```
프로젝터 화면 (1920×1200)
┌──────────────────────────────────────────┐
│                                          │
│          Keynote 슬라이드 (지금 그대로)    │
│                                          │
│                                          │
├──────────────────────────────────────────┤ ← 반투명 검은 띠 (자막 있을 때만)
│  The Lord said to Abram, "Go from ..."   │   영어 (흰색)
│  พระยาห์เวห์ตรัสกับอับรามว่า ...            │   태국어 (연한 노랑)
└──────────────────────────────────────────┘
노트북 화면: Keynote 발표자 화면 (지금 그대로) + 메뉴 막대에 작은 자막 프로그램 아이콘
```

- **만드는 방법 [의견]:** Python + PyObjC(맥 기본 창 기능을 Python에서 쓰는 도구)로 작은 맥 프로그램을 만듭니다.
  - Xcode 없이 이 Big Sur 맥에서 돌릴 수 있습니다.
  - 창 안에는 성도 휴대폰 화면과 **같은 자막 서버에 연결된 웹페이지**를 넣습니다. 그래서 자막 엔진은 하나이고, 화면만 둘(프로젝터, 휴대폰)이 됩니다.
- **창의 성질:** 테두리 없음, 배경 투명, 마우스 클릭 통과(Keynote 조작 방해 안 함), 최상위 레벨, 모든 데스크톱 공간에 표시.
- **운영자 없이 돌아가도록:**
  - 예배 전에 프로그램을 한 번 켜 두면 끝입니다. 맥 로그인 시 자동 실행도 가능합니다.
  - **말이 없으면 자막 띠가 자동으로 사라집니다.** 예: 8초 동안 말이 없으면 숨김. 그래서 찬양이나 기도 시간에 빈 띠가 화면을 가리지 않습니다.
  - 자막은 **한 번에 언어별 최대 2줄**만 보여 주고, 새 문장이 오면 자연스럽게 교체합니다.
  - 표시 언어(예: 영어+태국어)는 예배 전 설정에서 고릅니다. 기본값은 저장해 둡니다.
- **글자 크기:** 1920px 폭 기준 약 44~52px부터 시작해 현장에서 조정합니다.

## 4. Keynote 쪽에서 맞춰 주셔야 할 것 (작은 규칙 하나)
- 프로젝터는 16:10, 슬라이드는 16:9라면, 화면 위아래에 이미 검은 여백이 조금 있을 것입니다 [의견].
- 자막 띠는 슬라이드 **하단 약 15~20%**를 덮게 됩니다. 그래서 **설교 시간에 쓰는 슬라이드는 아래쪽 20%에 중요한 글자를 두지 않는** 템플릿 규칙을 권합니다.
- 찬양 가사 슬라이드는 자막이 자동으로 숨겨지므로 영향이 거의 없을 것으로 봅니다. 다만 목사님 핀마이크에 찬양 소리가 들어가면 자막이 뜰 수 있으니 현장에서 확인해야 합니다 [검증 필요].

## 5. 현장 시험 계획 (30분, 맥 + 프로젝터만 있으면 됨)
1. 오버레이 시험 프로그램을 실행합니다. 가짜 자막이 계속 흘러가게 해 둡니다.
2. Keynote 슬라이드쇼를 프로젝터에서 시작합니다.
3. 확인할 것:
   - ① 자막이 슬라이드 **위에** 보이는가
   - ② 슬라이드를 넘겨도 계속 보이는가
   - ③ 영상 슬라이드에서도 보이는가
   - ④ 노트북의 발표자 화면 조작에 방해가 없는가
   - ⑤ 글자 크기와 가독성
4. ①이 안 되면 → Keynote 설정에서 슬라이드쇼가 다른 앱 창을 허용하도록 바꾸는 옵션이 있는지 확인합니다 [검증 필요]. 그래도 안 되면 B안("윈도우에서 재생")으로 같은 시험을 합니다.

## 6. 성도 휴대폰 화면 (완료: 디자인 시제품)
- `web/listener.html`: QR로 들어가는 모바일 화면입니다(데모 모드로 자막이 흘러감).
  - 첫 화면은 **각 나라 글자로만** 언어 이름을 보여 줍니다. 한국어나 영어를 몰라도 고를 수 있습니다.
  - 언어를 고르면 **버튼과 안내문 전체가 그 언어로** 바뀝니다.
  - 다음에 다시 들어오면 고른 언어로 바로 열립니다.
  - 글자 크기 조절, 화면 켜두기, "AI 통역 · 오류 가능" 고지가 있습니다.
- 확인 필요: 태국어·중국어·베트남어 안내문은 AI가 작성했습니다. 데모 문장도 마찬가지입니다. 실제 휴대폰에서 태국어 줄바꿈이 단어 중간에서 끊기지 않는지도 봐야 합니다(시험 브라우저에서는 한 번 끊김).
