# 예배 실시간 번역 자막 — 리서치 및 기획 (초안 v0.1)

작성일: 2026-10-26
상태: 기획 단계 (코드 없음)

> **정직성 표기 규칙**
> - **[확인]** = 공식 문서나 프로젝트 페이지에서 확인한 내용 (출처 링크 있음)
> - **[업체 주장]** = 판매사 홍보 페이지에만 근거가 있어 독립 검증이 안 된 내용

## 0. 먼저 알려드릴 점

- 이전에 나눴던 대화와 올리신 장비 사진(믹서, 앰프, 맥북 기종)은 **이 세션에서 볼 수 없습니다.** claude.ai의 다른 대화 기록에는 접근 권한이 없고, Notion과 Google Drive도 검색해 봤지만 관련 자료를 찾지 못했습니다.
- 그래서 이 문서는 "믹서 → 맥북 → 프로젝터"라는 일반 구성을 기준으로 썼습니다. 장비 정보를 다시 알려주시면 "연결 방법" 부분을 구체적으로 고치겠습니다 (§7 질문 목록).

---

## 1. 목표

1. 마이크로 나가는 모든 음성(설교, 기도, 광고 등)을 맥북이 받는다.
2. 한국어 음성을 실시간으로 인식하고 영어·중국어·베트남어·태국어 등으로 번역한다.
3. 번역 자막을 빔 프로젝터 화면 **하단**에 띄운다. 기존 PPT 예배 순서 운영은 그대로 유지한다.
4. (확장) 번역된 **음성**도 제공한다. 예: 성도가 휴대폰과 이어폰으로 듣기.

---

## 2. 전체 구조 (어떤 방식을 택해도 공통)

```
[마이크] → [믹서] ──(AUX/Matrix 출력)──→ [USB 오디오 인터페이스] → [맥북]
                                                                   │
                                          ┌────────────────────────┘
                                          ▼
                              ① 음성 인식 (한국어 STT)
                              ② 번역 (영/중/베/태 …)
                              ③ (선택) 용어 교정 · 번역 음성(TTS)
                                          │
                     ┌────────────────────┼─────────────────────┐
                     ▼                    ▼                     ▼
              프로젝터 하단 자막    성도 휴대폰(QR 접속)     기록 저장(.srt/.txt)
              (언어 1~2개)          (각자 원하는 언어+음성)   (유튜브 자막 재활용)
```

**음성 입력 관련 [의견]**
- 맥북 내장 마이크로 스피커 소리를 받으면 울림과 잡음 때문에 인식률이 크게 떨어집니다. **믹서의 별도 출력(AUX send, Matrix, 또는 녹음용 출력)을 USB 오디오 인터페이스로 맥북에 넣는 방식**을 권합니다.
- 믹서에 USB 오디오 출력 기능이 있으면 인터페이스 없이 케이블 하나로 됩니다. 기종을 알려주시면 확인하겠습니다.
- 인식용 출력에는 **설교·기도 마이크만** 보내고, 찬양 반주는 빼거나 줄이는 것이 좋습니다. 반주와 노래는 인식 오류를 많이 만듭니다.

## 3. 리서치 결과 — 이미 있는 것들

### 3-1. 돈도 개발도 필요 없는 방법: PowerPoint 내장 실시간 자막·번역

- 한계 [의견]: 한 번에 한 언어만 보입니다. 신학 용어집을 넣을 수 없고, 번역 품질을 조정할 수 없으며, 휴대폰 배포나 음성 출력도 없습니다. Microsoft 365 구독이 필요합니다.

## 4. 화면 출력 방식 비교 — OBS냐, HTML이냐, 앱이냐

핵심 문제는 하나입니다. **맥에서 PowerPoint가 프로젝터 전체 화면을 차지하고 있을 때, 그 위에 자막을 어떻게 얹느냐.**

| 방식 | 작동 원리 | 장점 | 단점/위험 |
|---|---|---|---|
| **A. PowerPoint 내장 자막** | PPT가 직접 처리 | 개발 0, 운영 변화 0 | 1개 언어, 품질 조정 불가, 용어집 없음 |
| **B. OBS 합성** | PPT를 "창 모드"로 띄우고 OBS가 캡처 + 자막(브라우저 소스)을 합쳐서 OBS **전체화면 프로젝터**로 빔에 출력 | 자막 위치·디자인이 안정적. 같은 화면을 **유튜브 송출**에 그대로 사용 가능 | 운영자가 OBS를 익혀야 함. PPT 애니메이션·영상은 캡처 상태를 꼭 확인해야 함 |
| **C. HTML 자막 페이지** | 브라우저에 자막 페이지를 띄움 | 만들기 쉬움. OBS 소스, 휴대폰, 별도 모니터 **어디든 재사용** | 그 자체로는 전체화면 PPT **위에** 겹치기 어려움 (B나 D와 결합해야 함) |
| **D. 맥 전용 투명 오버레이 앱** | 항상 위에 떠 있는 투명·클릭 통과 창을 프로젝터 하단에 배치 | OBS 없이 PPT 그대로 사용 | **[의견]** macOS 전체화면 슬라이드쇼 위에 정상적으로 뜨는지 **검증이 필요**합니다(창 레벨·Spaces 설정 문제). 직접 확인한 사례는 찾지 못함 |

### 추천 [의견]
**"엔진 하나 + 출력 여러 개" 구조로 만드는 것을 권합니다.**

1. **엔진**: 맥북에서 도는 작은 프로그램(Python). 오디오를 받아 인식·번역한 뒤 결과를 로컬 웹소켓으로 내보냅니다.
2. **출력은 모두 HTML 한 벌로**:
   - `/overlay` → OBS 브라우저 소스 (방식 B), 투명 배경
   - `/display` → 별도 화면/TV용
   - `/view?lang=vi` → 성도 휴대폰 (QR 접속, 언어별로 다르게, 번역 음성 재생)
3. 이렇게 하면 **OBS를 쓸지, 오버레이 앱을 쓸지는 나중에 바꿀 수 있습니다.** 엔진은 그대로 둡니다.
   Church Cap 오픈소스가 이 구조를 쓰고 있어서 검증된 접근이라고 봅니다.

**프로젝터에는 1~2개 언어만** 띄우는 것을 권합니다. 화면 하단에 4개 언어가 동시에 올라가면 읽을 수가 없습니다. 나머지 언어는 휴대폰으로 보게 합니다. 예: 프로젝터는 영어, 베트남·태국·중국 성도는 휴대폰.

## 5. 설교 번역에서 특히 중요한 부분 (목회 맥락)

- **용어집(Glossary)**: 하나님/God, 언약/covenant, 칭의/justification, 요리문답/Catechism, 하이델베르크 요리문답/Heidelberg Catechism, 성도/saints·congregation, 고유명사(교회명, 지명, 성경 인물) 등. STT 단계(인식 힌트)와 번역 단계(용어 강제) 양쪽에 적용합니다.
- **설교 원고 사전 입력 (선택)**: 원고가 있으면 미리 넣어 인식과 번역 정확도를 높일 수 있습니다. [의견] 효과는 테스트로 확인해야 합니다.
- **성경 구절**: "창세기 12장 1절" 같은 인용을 감지하면, 해당 언어의 공인 번역본 본문으로 대체하는 기능을 생각해 볼 수 있습니다. **저작권이 있는 역본이 많아서** 공개(public domain) 역본(예: 영어 KJV/WEB)부터 검토해야 합니다.
- **화면 고지**: 자막 옆에 "AI 자동 번역 — 오역이 있을 수 있습니다" 같은 작은 표기를 권합니다. 신학적 오역이 그대로 권위를 갖지 않도록 하기 위해서입니다.
- **운영자 제어**: 찬양 시간 자막 끄기(일시정지 키), 마지막 문장 지우기, 글자 크기 조절.
- **지연 시간 기대치 [의견]**: 실시간 번역이라도 한국어는 문장 끝(서술어)이 나와야 뜻이 정해지므로, 보통 **2~5초 정도 지연**은 감수해야 할 것으로 봅니다.
