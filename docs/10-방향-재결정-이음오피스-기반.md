## 1. 왜 다시 결정하는가
목사님 판단: 이음오피스 오픈소스를 활용하면 **더 쉽고, 비용 없이** 할 수 있다.
→ 검토 결과 **방향 자체는 옳다고 봅니다** [의견]. 핵심 이유는 다음과 같습니다.

| | A안: Keynote + 자막 오버레이 | **이음오피스 기반 (새 주안)** |
|---|---|---|
| 가장 큰 위험 | 자막 창이 Keynote 전체화면 **위에 뜨는지 모름** | 자막이 **발표 화면의 일부**로 그려지므로 그 위험이 없음 |
| 화면 제어 | Keynote는 고칠 수 없음 | 오픈소스(Apache-2.0)라 **청중 화면을 직접 수정** 가능 [확인] |
| 매주 PPT 작업 | 손으로 수정 | 이음오피스의 AI·명령줄로 **찬양·찬송·성경 구절·이름 교체를 자동화**할 여지 [의견] |
| 비용 | 0 | 0 (오픈소스) |

## 2. 반드시 넘어야 할 벽: 교회 맥의 macOS 버전
- 이음오피스는 Electron 43 기반이고 Mac판은 **macOS 12 이상** [확인: README].
- **Electron 38부터 macOS 11(Big Sur) 지원이 끊겼습니다** [확인: [Electron 38 릴리스 노트](https://electronjs.org/de/blog/electron-38-0), [MongoDB Compass 이슈](https://jira.mongodb.org/browse/COMPASS-9852)]. 교회 MacBook Air는 Big Sur에서 더 올릴 수 없습니다.

넘는 방법 세 가지:
| 방법 | 비용 | 평가 [의견] |
|---|---|---|
| **① 목사님 개인 맥(macOS 12 이상)을 주일에 사용** | 0 | **가장 현실적.** 이음오피스가 이미 설치되어 있음 |
| ② 이음오피스를 **Electron 37로 낮춰 빌드**해 Big Sur에서 실행 | 0 | 가능은 하지만 6단계 낮춰야 해서 깨지는 부분이 생길 수 있고, Electron 37은 보안 지원이 끝난 버전. **비상용으로만** |
| ③ 교회 맥 교체 | 있음 | 장기적으로는 필요할 수 있음(Big Sur 자체도 보안 업데이트 종료) |

## 3. 새 구조
```
[핀마이크] → [맥 (macOS 12+)] ─ 이음오피스(우리 수정판)
                                  ├ 노트북: 발표자 화면 (지금처럼)
                                  └ 프로젝터: 청중 화면 = 슬라이드 + [하단 자막 띠] ← 자막 서버에서 받음
                                          │
                    자막 서버(클라우드: Gemini 통역 · 원고 추적 · 성도 휴대폰 음성)
```
- 우리가 고치는 곳은 **청중 화면 한 군데**입니다 (`apps/slides/src/renderer/components/AudienceView.tsx`) [확인: 발표자/청중 창 분리 구조].
  - 그 화면 맨 아래에 자막 띠를 추가하고 자막 서버에 연결합니다.
  - 말이 없을 때 자동으로 숨기는 기능은 기존 기획 그대로 넣습니다.
- 성도 휴대폰 화면(`web/listener.html`)과 Gemini 통역·원고 추적 설계는 **그대로** 갑니다.
- 수정판은 원본 저장소를 복제(포크)해 관리합니다. 원본이 업데이트되면 주기적으로 반영합니다.
  - 고치는 범위를 청중 화면 한 군데로 최소화해서 이 부담을 줄입니다.
- Mac용 설치 파일(dmg)은 맥에서 만들어야 합니다. 그래서 **GitHub의 맥 빌드 서버(Actions)**로 자동 빌드하거나, 목사님 맥에서 직접 빌드합니다 [의견: 저장소 설정 확인 필요].
